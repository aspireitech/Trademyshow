Deployment walkthrough

Putting TradeMyShow on Azure

Written for someone who has never used Azure. Every click is spelled out, every command can be copied whole. You do not need to understand what any of it means to get to the end.

0

Before you start

Three things to have ready. Skip nothing here — each one blocks a later part.

In the Azure website
  1. An Azure account. Sign up at azure.microsoft.com/free. It asks for a credit card to verify identity. New accounts get $200 of free credit for 30 days, so the first month is very likely free.
  2. Access to the code. You need the GitHub repository aspireitech/Trademyshow. If it is private, do Part 5's private repository note before you start.
  3. A terminal. On Windows, press Start and open PowerShell. On Mac, press ⌘+Space and type Terminal. Both are already installed — nothing to download.
!
A word on what you are building. This creates a sandbox: a working, public demo where the share prices are invented rather than real. It is for showing people. Turning it into a real business needs the separate items in the project's cost and legal notes.
1

Create a resource group

A resource group is just a labelled folder. Everything you make goes inside it, so that later you can delete the whole thing in one click instead of hunting for pieces.

In the Azure website

Home → search bar at the top → Resource groups

  1. Go to portal.azure.com and sign in.
  2. In the search bar at the very top, type resource groups and click the result.
  3. Click + Create (top-left of the page).
  4. Fill in the two fields below, then click Review + create, then Create.
FieldWhat to enterWhy
SubscriptionLeave as isYour billing account
Resource grouptrademyshow-rgAny name works; this one is easy to type
RegionPick the one nearest youCloser means a faster site
✓
Checkpoint. You should now see trademyshow-rg in your list of resource groups. It is empty. That is correct.

Microsoft's own version of this step, with screenshots: Manage resource groups

2

Create the virtual machine

A virtual machine is a computer you rent in Microsoft's data centre. This is the longest form in the whole process. Change only the fields listed below and leave every other setting alone.

In the Azure website

Home → search Virtual machines → + Create → Azure virtual machine

FieldWhat to chooseWhy
Resource grouptrademyshow-rgThe folder you just made
Virtual machine nametrademyshow-vmJust a label
RegionSame as Part 1Keep everything together
Availability optionsNo infrastructure redundancyCheapest; fine for one server
Security typeStandardDefault is fine
ImageUbuntu Server 24.04 LTSThe operating system the setup script expects
SizeStandard_B2s (2 vCPU, 4 GiB)Click "See all sizes" to find it. Smaller sizes run out of memory while building.
Authentication typeSSH public keyFar safer than a password
UsernameazureuserRemember this — you type it in Part 4
SSH public key sourceGenerate new key pairAzure makes the key for you
Key pair nametrademyshow-keyJust a label
Public inbound portsAllow selected portsControls who can reach the server
Select inbound portsSSH (22), HTTP (80), HTTPS (443)SSH to manage it, HTTP/HTTPS for visitors
  1. Click Review + create, then Create.
  2. A box appears: Generate new key pair. Click Download private key and create resource.
  3. A file called trademyshow-key.pem downloads. Move it somewhere you will not lose it.
  4. Wait 2–4 minutes for deployment, then click Go to resource.
  5. Copy the Public IP address shown on that page and paste it somewhere handy.
!
That .pem file is the only key to your server. It downloads once and Azure does not keep a copy. Lose it and you cannot get back in — you would have to delete the VM and start this part again.
✓
Checkpoint. You have a running VM, a public IP address written down, and the .pem file saved.

Microsoft's version with screenshots: Create a Linux VM in the portal

3

Check the doors are open

Only needed if you missed the ports in Part 2. Thirty seconds to verify.

In the Azure website

Your VM → left menu → Networking → Network settings

  1. Look at the inbound rules list. You want to see rules allowing ports 22, 80 and 443.
  2. If any is missing: Add inbound port rule → set Destination port ranges to the number → Protocol: TCP → Action: Allow → Add.
✓
Checkpoint. Ports 22, 80 and 443 all show as allowed.
4

Connect to your server

From here on you are typing rather than clicking. SSH is simply a way to control that rented computer from yours.

In the black terminal window

Mac or Linux

# Go to wherever the key downloaded (usually Downloads)
cd ~/Downloads

# Lock the key down — SSH refuses to use a key others can read
chmod 400 trademyshow-key.pem

# Connect. Replace the IP with the one you copied in Part 2.
ssh -i trademyshow-key.pem azureuser@YOUR-IP-ADDRESS

Windows (PowerShell)

# Go to wherever the key downloaded
cd ~\Downloads

# Connect. Replace the IP with the one you copied in Part 2.
ssh -i trademyshow-key.pem azureuser@YOUR-IP-ADDRESS

The first time, it asks "Are you sure you want to continue connecting?" — type yes and press Enter.

✓
Checkpoint. The prompt changes to something like azureuser@trademyshow-vm:~$. You are now typing commands on the server, not on your own computer.
!
If Windows says permissions are too open, right-click the .pem file → Properties → Security → Advanced → Disable inheritance → remove everyone except your own user.
5

Install everything

One script does all of it: installs the software, downloads the code, builds the site, starts it, and sets it to restart automatically if the server reboots.

In the black terminal window 
# Download the setup script
curl -fsSL https://raw.githubusercontent.com/aspireitech/Trademyshow/claude/stock-analytics-ai-portal-j7ftsb/scripts/azure-vm-setup.sh -o setup.sh

# Make it runnable, then run it
chmod +x setup.sh
sudo ./setup.sh

It asks four questions. Press Enter to accept the default for the first two, leave the domain blank for now, and answer Y to the sandbox question. Then it runs for 5–8 minutes on its own.

!
Private repository? If the download or clone fails with a permission error, the repository is private. Create a token at github.com/settings/tokens (choose Tokens (classic) → Generate new token → tick repo → copy it), then when the script asks for the repository URL, paste this form instead:
https://YOUR-TOKEN@github.com/aspireitech/Trademyshow.git
✓
Checkpoint. The script finishes with a box showing your web address and the demo login details. It also prints ✓ Health check passed.
6

Open your site

It is already live.

In your web browser
  1. Type http://YOUR-IP-ADDRESS into the address bar.
  2. An orange SANDBOX banner across the top confirms it is running in demo mode.
  3. Sign in with demo@trademyshow.com / Sandbox!Demo2026.
  4. For the business metrics view, sign in as admin@trademyshow.com / Sandbox!Admin2026.
✓
Checkpoint. You are looking at three watchlists with prices, charts and written insights. This is the whole product working.
!
Your browser may warn that the site is Not secure. That is expected without a domain name — Part 7 fixes it. Do not put real personal data in until then.
7

Add your own domain and the padlock (optional)

Skip this if the IP address is enough for now. You can come back any time.

At your domain registrar

GoDaddy, Namecheap, Cloudflare — wherever you bought the domain

  1. Find DNS settings or DNS management.
  2. Add a record: Type A, Name @, Value your VM's IP address.
  3. Add a second: Type A, Name www, Value the same IP address.
  4. Wait 10–30 minutes for it to take effect.
In the black terminal window 
sudo ./setup.sh

Run it again and enter your domain when asked. It requests a free certificate, switches the site to https://, and sets it to renew itself automatically.

✓
Checkpoint. Your domain loads with a padlock in the address bar.
8

The five commands worth knowing

Everything you need for day-to-day running. Connect with the Part 4 command first.

In the black terminal window 
# Is it running?
sudo systemctl status trademyshow

# Watch what it is doing, live. Press Ctrl+C to stop watching.
sudo journalctl -u trademyshow -f

# Turn it off and on again — fixes more than you would think
sudo systemctl restart trademyshow

# Change settings such as API keys or your company details
sudo nano /opt/trademyshow/.env.production
#   Ctrl+O then Enter saves. Ctrl+X exits.
#   Then: sudo systemctl restart trademyshow

# Update to the newest code
sudo ./setup.sh

When something goes wrong

Find your symptom. Every fix is one command.

What you seeWhat to do
Browser says the site can't be reachedCheck ports 80 and 443 are open (Part 3), then run sudo systemctl status trademyshow
"Permission denied (publickey)" when connectingWrong key file, wrong username, or run chmod 400 on the .pem file
Setup script stops on "npm ci"Not enough memory. The VM must be Standard_B2s or larger.
Site loads but shows an error pagesudo journalctl -u trademyshow -n 50 shows the reason
Demo data has disappearedRe-run the seed: the command is printed at the end of the setup script
Certificate request failedDNS has not caught up. Wait 30 minutes, then sudo certbot --nginx -d yourdomain.com
Everything is broken and you want a clean startDelete the resource group (Part 9) and begin again at Part 1. Nothing is lost that matters.
!
Before you charge anyone. Open /opt/trademyshow/.env.production and fill in the LEGAL_ lines with your real company details. While they are blank, your own Terms page displays a warning saying so.

The setup script this guide runs is scripts/azure-vm-setup.sh in the repository. It is readable — every step it takes is commented.
